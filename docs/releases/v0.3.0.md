# v0.3.0: Door-driven command-mode sweeps

For Pantry Hub v0.3.0, which runs a timed sweep over TCP when a door closes.

**Sweep lifecycle**
- `async with client.inventory(duration=45) as sweep: async for tag in sweep:`.
  Leaving the block always sends stop and waits for the reader's
  acknowledgement, bounded by `stop_drain` (now defaults to `timeout`).
- `__del__` is only a last-resort safety net and logs a WARNING when it has to
  stop an abandoned stream.

**Sweep result:** `sweep.result` (a `SweepResult`) once the stream has ended:
`end_reason` (`duration_elapsed` | `stopped` | `connection_lost` | `error`),
`completed`, `started_at`, `ended_at`, `elapsed`, `reports`, `unique_epcs`,
`unique_count`, `per_antenna_counts`, `dropped`, `stop_sent`,
`stop_acknowledged`, `error`.

**Long-lived connections**
- `await client.ping()`: firmware-version round trip, returns seconds.
- `keepalive_interval_s` (default off): ping after that many idle seconds; a
  ping that times out drops the connection so it is noticed.
- `auto_reconnect` (default off): reconnect with exponential backoff and
  jitter after an unexpected drop, then call `on_reconnect`.
- `connect(retries=N)`: retry the first connection with backoff.
- `stop_on_connect` (default off): send stop inventory after every
  (re)connect, as Chainway's SDK does, to clear a reader left running.

**FakeUR4 scenarios** (`aiochainway.testing`)
- `ScriptedTag`: presence over time, per-tag `read_probability` (seeded
  flicker), per-tag antennas (only enabled ports report).
- New faults: `disconnect_after_s`, `stop_ack_delay`, `idle_timeout_s`.

**CLI:** `inventory` prints a sweep summary and takes `--stop-first`; new `ping`,
`sweep` (repeatability: unique-EPC min/max/mean/variance) and `idle` (idle TCP
survival).

**Docs:** door-driven sweep pattern in the integration notes; a new
hardware-validation §E (45 s sweep repeatability, 60 min idle-session
survival, power draw idle vs reading).

No protocol changes. Whether the reader drops idle TCP sessions is recorded as
unknown (`inferred`) until §E.2 is run on hardware.

**Behaviour changes:** `stop_drain` defaults to `timeout` (was 0.5 s);
abandoning a stream without `async with` now logs a WARNING.
